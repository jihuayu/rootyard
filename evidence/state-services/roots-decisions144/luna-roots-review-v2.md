# Luna Max roots re-review v2 (read-only)

I rechecked the current `retention_root/*` after Root's fixes. No Cargo, Git, native verifier, PostgreSQL service or source edits were run.

The earlier SQL/schema, shared-lock-order, full-receipt-scope, realm-epoch, deadline and release-before-register quota findings are closed in the current tree. The two cleanup escapes are also fixed: T2 computes the complete check/seal `Result` before `rollback_reads` (`read.rs:126-141`); T1 `read_retained` and historical `get` put fallible result construction in `and_then` before their bounded rollback (`read.rs:164-190`, `pg_release.rs:250-265`). An error from validation, binding recomputation or sealing therefore reaches cleanup before it is returned. `query_receipt` keeps its fallible work inside `before_deadline` and also rolls back before return.

I found no path that mints a new byte-read view after release or repository deletion. T1 requires an active head before native work. T2 takes the live gate `FOR SHARE` and the root head `FOR SHARE`, rechecks the complete realm, active generation and register/binding digests, then returns the sealed view only after rollback succeeds (`read.rs:89-141`; locks in `sql.rs:24-34,138-146`). If deletion wins, the gate lookup returns absent; if release wins before T2, the head is released. A release/delete after T2's successful linearization cannot revoke an already-returned in-memory view. After whole-repository deletion, `get`/receipt retain metadata, while `materialize` refuses byte access; the ignored integration case states this explicitly (`tests/ref_store_retention_roots.rs:304-335`). Source-pin expiry is immaterial because T1 reads the root-owned capture and complete retained pack locators.

The quota audit found no demonstrated logical-byte undercount: actual ref names/OIDs, every locator string, captured header/digests, release reason and receipt JSON are included; fixed column widths and conservative per-row overhead cover the bounded stored fields (`usage.rs:79-189`). Registration/release compute the charge and apply it before retained inserts (`pg_register.rs:177-190`, `pg_release.rs:155-179`), including a release-created head. The current tests verify root-count refusal and atomicity (`tests/ref_store_retention_roots.rs:397-445`), but not the `logical_bytes` ceiling with maximum-width ref/locator values. This is a remaining quota-regression evidence gap, not a code undercount established by this review.

No roots-specific must-fix remains from this pass. Do not claim the quota ceiling has end-to-end evidence until a real logical-byte-boundary/refusal test is added and run; the roots integration tests are ignored unless their real PG/S3/Git fixture is enabled.
