## Architecture
Rootyard is a high-assurance Git hosting, CI mirror, distributed sharding, and workspace/object-storage system written in Rust (`edition = "2024"`, Axum 0.8, `deadpool-postgres` / `tokio-postgres`).
To support conflict-free parallel development across Tier-1 (`M1`–`M5`, `DONE`), Tier-2 (`M6`–`M11`, `DONE`), Tier-3 (`M12`–`M17`, `DONE`), Tier-4 (`M18`–`M22`, `DONE`), and Tier-5 (`M23`–`M28`, `DONE`):
- **Router Decoupling & Anti-Monolith Architecture (`src/lib.rs`)**: `src/lib.rs` composes self-contained domain routers via `.merge(<domain>::routes())` for `browse`, `ci_pins`, `ci_checkouts`, `reliability`, `forge`, `pulls`, `lfs`, `webhooks`, `members`, and (in Tier-3) `web` and `sharding` (11 HTTP domain routers total). Each domain entry file (`src/<domain>.rs`) MUST remain a regular file (`< 100` lines, `< 120`–`150` max for `view_lab.rs` / `mirror.rs` / `workspace_lab.rs`, zero `src/<domain>/mod.rs`) exposing `pub fn routes() -> Router<Arc<AppState>>` and delegating implementation to high-cohesion submodules under `src/<domain>/*.rs` (`< 500` lines for Tier-5 submodules, `< 550`–`600` lines for existing submodules, `< 850` for `src/pando_lab/*.rs`). **No giant monolithic files ("不要给我一个雷霆大文件") are permitted.**
- **Shared Auth, 5-Role RBAC & Transaction Helpers (`src/auth.rs`, `src/members/rbac.rs`)**: Domain handlers (including `src/web/handlers.rs` and `src/sharding/*`) use `auth::authenticate`, `auth::authorize_repo(&tx, &actor, &owner, &name, write)`, `auth::authorize_repo_with_role(&tx, &actor, &owner, &name, min_role)`, `auth::verify_token`, `auth::finish_tx(tx, &actor, write)`, and `auth::idempotency_key(&headers)` across the 5-level role hierarchy (`read` < `triage` < `write` < `maintain` < `admin`).
- **Server-Side Git Mutations, Reliability & Storage Fencing (`src/storage.rs`, `src/reliability.rs`, `src/sharding/fencing.rs`, `src/journal.rs`, `src/events.rs`)**: Any server-side `git update-ref` or push must acquire `state.git_slots` and `state.storage.write_lock(repo_id)`, verify `reliability::before_push` (which in Tier-3 also enforces `sharding::fencing::check_before_push` dual-layer lease, `fence_epoch`/`route_epoch`, and `storage_generation` barriers), invoke `git` with `-c core.hooksPath=/dev/null` and `--no-replace-objects`, and publish via `journal::{begin,finish,retire}` + `events::publish`.
- **Database Migration & Schema Baseline Synchronization (`migrations/001..060`, `src/db.rs`, `src/backup.rs`, `schema/`)**:
  - **Part I (`M12` — Schema `050` Baseline Promotion)**: Promotes `src/webhooks/040_webhooks.sql` (+3 tables) and `src/members/050_members_rbac.sql` (+4 tables, +1 column `forge_branch_rules.prevent_self_approval`, -5 legacy constraints, +1 FK constraint, +1 trigger function, +5 triggers) into top-level `migrations/040_webhooks.sql` and `migrations/050_members_rbac.sql` (eliminating `BIGSERIAL` `relkind='S'` sequence objects in favor of `BIGINT` with monotonic subquery allocation, and ensuring `ON CONFLICT DO NOTHING` on `schema_migrations`), updating `src/db.rs` (`SCHEMA_VERSIONS = &[1, 2, 3, 6, 7, 8, 9, 20, 30, 40, 50]`), `src/backup.rs` (`30` permanent public tables), and `schema/050_*` catalog snapshots.
  - **Part II (`M16` — Staged `060_sharding_fencing.sql`)**: Stages `src/sharding/060_sharding_fencing.sql` (+4 tables: `shard_nodes`, `shard_virtual_buckets`, `repository_shard_routes`, `shard_failover_operations`) with idempotent `sharding::models::ensure_schema(&pool)` during parallel Tier-3 execution.
  - **Part III (`M17` — Schema `060` Final Convergence)**: Promotes `060_sharding_fencing.sql` into top-level `migrations/060_sharding_fencing.sql`, `src/db.rs` (`SCHEMA_VERSIONS = &[1, 2, 3, 6, 7, 8, 9, 20, 30, 40, 50, 60]`), `src/backup.rs` (`34` permanent public tables), and `schema/060_*` catalog snapshots.
