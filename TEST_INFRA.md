# Rootyard Requirement-Driven 4-Tier E2E Test Infrastructure (`TEST_INFRA.md`)

## 1. Test Philosophy

### 1.1 Requirement-Driven Opaque-Box Design
Rootyard's 4-tier test suite (`tests/e2e_tiers.py`) is designed directly from the authoritative requirements in `PROJECT.md`, `.agents/teamwork/ORIGINAL_REQUEST.md`, `docs/parallel-development.md`, and the 11 design chapters (`docs/design/01`–`11`). Every test verifies external behavioral contracts, HTTP/CLI interfaces, native Git object/ref mutations, SQL schema constraints, and operational safety invariants rather than internal private implementation details.

### 1.2 Zero Fake / Placeholder Assertions
Every test case in `tests/e2e_tiers.py` performs genuine, deterministic execution using Python 3's standard library (`sqlite3`, `subprocess`, `hashlib`, `hmac`, `http.server`, `zlib`, `tempfile`, `os`, `stat`) and the real `/usr/bin/git` binary:
- **Real Git Subprocesses**: Spawns real `/usr/bin/git` plumbing and porcelain operations (`git init --bare`, `git hash-object -w`, `git mktree`, `git commit-tree`, `git update-ref --no-deref`, `git update-ref --stdin -z --no-deref`, `git merge-base --is-ancestor`, `git merge-tree --write-tree`, `git diff`, `git for-each-ref`, `git rev-list --left-right --count`, `git rev-list --objects`, `git ls-tree -z -l`, `git cat-file`, `git pack-objects`, `git index-pack --stdin --strict`, `git fsck --full --strict`, `git check-ignore`, `git gc --prune=now`) in isolated temporary directories with `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, and `core.hooksPath=/dev/null`.
- **Real Cryptographic, HMAC & Binary Stream Verification**: Computes real SHA-1 (`hashlib.sha1`), SHA-256 (`hashlib.sha256`), and RFC 2104 HMAC-SHA256 (`hmac.new` + `hmac.compare_digest` for `X-Rootyard-Signature-256: sha256=<hex>`) digests, parses raw Git packv2 headers/trailers, decompresses `zlib` object streams, and decodes binary `OBJ_OFS_DELTA` (type 6) and `OBJ_REF_DELTA` (type 7) copy/insert instruction streams with cycle and inflation guards.
- **Real Loopback HTTP Webhook Delivery**: Spawns an ephemeral local `http.server.HTTPServer(("127.0.0.1", 0))` background thread (`LoopbackWebhookReceiver`) to receive real HTTP/1.1 `POST` webhook payloads, verify `X-Rootyard-Signature-256` headers over the wire, and return configurable HTTP status sequences (`200`, `502`, `503`, `500`) driving exponential backoff and dead-letter transitions.
- **Real Atomic Filesystem Staging & Cross-Node CAS Transfer**: Executes chunked LFS uploads into `<data_dir>/lfs/<repo_id>/.tmp-<uuid>` and cross-node workspace CAS blob transfers into `blobs/<sha256[0..2]>/<sha256>` via `.tmp-<uuid>` with mode `0o600`, `O_NOFOLLOW`, `os.fsync()`, SHA-256 + `st_nlink == 1` verification, and atomic `os.replace()` promotion.
- **Real Relational Constraint & Idempotency Enforcement**: Enforces all SQL `CHECK`, `PRIMARY KEY`, `UNIQUE`, `TRIGGER`, and `FOREIGN KEY` constraints from migrations `001`–`050` (`forge_pull_counters`, `forge_pulls`, `forge_pull_reviews`, `forge_check_runs`, `forge_branch_rules`, `forge_creation_requests`, `lfs_objects`, `ci_checkout_jobs`, `ci_mirror_evictions`, `forge_webhooks`, `forge_webhook_deliveries`, `forge_webhook_callbacks`, `repository_collaborators`, `repository_teams`, `repository_team_members`, `repository_audit_log`, `pando_repositories`, `pando_migrations`, `git_operations`, `outbox_events`) and deterministic `events::event_id` SHA-256 (`b"rootyard-ref-event-v1\0"`) computation.

### 1.3 Anti-Monolith Architectural Enforcement ("不要给我一个雷霆大文件")
To prevent monolithic source files, the test suite enforces modular decomposition across all Phase 1 and Phase 2 tracks:
- Domain root files (`src/pulls.rs`, `src/browse.rs`, `src/lfs.rs`, `src/mirror.rs`, `src/webhooks.rs`, `src/members.rs`, `src/ci_pins.rs`, `src/ci_checkouts.rs`, `src/workspace_lab.rs`) must remain regular files (`src/<domain>.rs`, never replaced by `src/<domain>/mod.rs`).
- Every HTTP domain module (`browse`, `ci_pins`, `ci_checkouts`, `reliability`, `forge`, `pulls`, `lfs`, `webhooks`, `members`) must expose `pub fn routes() -> Router<Arc<AppState>>` without inline SQL in the thin router entry file.
- Modular domain root files (`pulls.rs`, `browse.rs`, `lfs.rs`, `webhooks.rs`, `members.rs`) must remain `< 100` lines (`mirror.rs` and `workspace_lab.rs` `< 150` lines), domain submodules `< 600` lines (`mirror/*` `< 700` lines, `workspace_lab/core.rs` `< 1150` lines), and `src/pando_lab/*.rs` `< 850` lines.

### 1.4 Progressive Migration & Multi-Track Awareness (`M1`–`M5` and `M6`–`M11`)
- During `M7`–`M10` and `M13`–`M16` parallel track execution, new SQL migrations are staged inside each track's owned directory (`src/webhooks/040_webhooks.sql`, `src/members/050_members_rbac.sql`, `experimental/pando/schema.sql`, `src/sharding/060_sharding_fencing.sql`) so `migrations/` remains at its baseline (`030` in Tier 2, `050` in Part 1 / Tier 3) without breaking `tests/schema_baseline.py` or `tests/test_parallel_boundaries.py`.
- `tests/e2e_tiers.py` uses `get_track_migration_sql(candidate_relpaths, fallback_sql)`, `SchemaBoundaryIntegrationFixture.verify_part1_schema_050_closure()`, and `SchemaBoundaryIntegrationFixture.verify_part3_convergence_and_tier3_governance()` to inspect migrations and routers in either staged parallel mode (`M13`–`M16`) or unified post-integration mode (`M17`).

## 3. Test Architecture (`tests/e2e_tiers.py`)

`tests/e2e_tiers.py` is structured around 19 self-contained reference and verification fixtures that drive all 591 tests across 4 `unittest.TestCase` classes:

1. **`GitRepoFixture`**:
   - Creates isolated bare Git repositories (`git init --bare --object-format=sha1`) and builds commit histories via fast Git plumbing (`git hash-object -w`, `git mktree`, `git commit-tree`, `git update-ref --no-deref`).
   - Exposes real Git operations: `resolve_ref`, `cat_file_type`, `cat_file_size`, `cat_file_bytes`, `is_ancestor`, `merge_base`, `ahead_behind`, `unified_diff`, `merge_tree_commit`, `cas_update_ref`, and `atomic_ref_transaction` (`git update-ref --stdin -z --no-deref`).
2. **`Track1PullsEngine`**:
   - Backed by an in-memory `sqlite3.Connection` enforcing the exact DDL and `CHECK` constraints of `009_forge_pulls.sql` and `007_forge_idempotency.sql` (`forge_pull_counters`, `forge_pulls`, `forge_pull_reviews`, `forge_check_runs`, `forge_branch_rules`, `forge_creation_requests`, `git_operations`, `outbox_events`).
   - Drives PR creation/listing/patching/diffing (`F1`, `F2`), SHA-bound reviews (`F3`), monotonic `(attempt, sequence)` check runs (`F4`), branch protection rules (`F5`), same-generation atomic merges (`F6`), and paired backup snapshot/restore verification (`F7`).
3. **`Track2BrowseEngine`**:
   - Executes read-only Git inspection (`GET /refs` excluding `refs/rootyard-ci/*`, `GET /commits`, `GET /commits/{oid}`, `GET /tree`, `GET /blob`, `GET /compare` with `--no-replace-objects` and size caps) (`F8`, `F9`), atomic multi-ref CAS transactions (`POST /ref-transactions` via `git update-ref --stdin -z --no-deref` with branch protection & `Idempotency-Key` support) (`F10`), and storage backend gateway routing (`GET/PATCH /api/repos/{owner}/{name}/backend`, `GET /storage-route`) (`F36`).
4. **`Track2LfsEngine`**:
   - Backed by `<data_dir>/lfs/<repo_id>/` on disk and `lfs_objects` in SQLite (`020_lfs_objects.sql`).
   - Implements Batch API (`POST .../info/lfs/objects/batch` with `application/vnd.git-lfs+json`) (`F11`), chunked streaming `PUT` into `.tmp-<uuid>` (`0o600`, `O_NOFOLLOW`, `fsync`, SHA-256 verification, atomic rename, quota enforcement), `POST .../verify`, streaming `GET`, and `src/backup.rs`-compatible `manifest.json` volume inventory verification (`F12`).
5. **`MirrorPinCheckoutFixture` & `SyncRateLimiter`**:
   - Manages primary bare repos (`primary_data/repos/<repo_id>.git`), durable source pins (`primary_data/ci-pins/<repo_id>/<job>.json` + `refs/rootyard-ci/jobs/<job>`), mirror snapshots (`mirror_data/repos/<repo_id>/<snapshot>/repository.git`), mirror pins (`pin-<gen>-<oid>.json`), closure-isolated `job-views/<gen>-<oid>.git` (via `git pack-objects --revs --no-reuse-delta --no-reuse-object`), checkout leases (`ci_checkout_jobs`), LRU watermark eviction (`ci_mirror_evictions`), `SyncRateLimiter`, `/mirror-status`, and `/metrics` (`F13`, `F14`, `F15`).

Evaluates `.gitignore` + `.rootyardignore` rules while preserving tracked files, computes live `status` and dirty manifests, generates and applies 3-way `changesets` atomically, performs incremental `sync-dirty`, and projects/verifies read-only checkpoint views (`F18`).
