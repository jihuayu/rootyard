# Round 5 worker metrics and typed remote-failure evidence

The private metrics endpoint now exports 91 fixed-cardinality samples on a healthy scrape, including capture freshness, expired local leases, and seven maintenance job kinds. Failed snapshots return503 and omit SQL-derived values while retaining process counters. Database-wide job metrics must be deduplicated across exporters; workspace series require an external volume label. Retained failed jobs are history, not unresolved retryable work. No repository/user/token identifier becomes a metric label.

Schema135 adds a partial covering index for the exact queried kinds/states, skipping retained succeeded history. The [owned PostgreSQL default-planner drill](round5-observability-evidence/default-planner.json) seeded 100,000 succeeded rows plus six counted jobs, used no planner override, and observed an index-only scan returning six rows with two shared-hit blocks. This proves that fixture plan, not production latency or a hard scan bound for retained failed history.

Archive format11 binds schema135. Format10/schema134 remains frozen and upgrades only with `--allow-legacy-schema134`. The [genuine previous-binary Pando archive drill](round5-observability-evidence/legacy134-restore.json) passed all seven cases: strict opt-in, fresh database, one new authority for two real repositories, old cookie rejection, preserved API access, clone/fetch/fsck, and intact source objects. Actual SQL-generated and actual-binary fresh/restored/upgraded/custom-search-path catalogs also passed. The [schema135 receipt](round5-observability-evidence/build-schema135.json) identifies the executable for that drill and the initial [metrics](round5-observability-evidence/schema135-metrics.json) and [capture](round5-observability-evidence/schema135-workers.json) checks.

Internal remote diagnostics now retain only a finite operation/status classification through S3 retries, GET/range body errors, multipart response bodies and shared LFS hydration. Error text, URLs and credentials are excluded. The [request-error drill](round5-observability-evidence/request-errors.json) passed eleven checks, including real PostgreSQL 23503 and pg_sleep(6) cancelled by a five-second statement timeout (57014). The [Garage streaming drill](round5-observability-evidence/remote-stream-failures.json) passed real successful hydration, scripted 502 retries, HTTP 200/full Content-Length followed by a short body, two correlated waiter errors, no partial final/staging files, a fresh successful retry and cancellation cleanup. The test explicitly checks the upstream fault stimulus and fixed 503 JSON response.

The [integrated receipt](round5-observability-evidence/build-integrated.json) records source `0138b58` and input digest `47af4e6c1cf6af07488fdd22cab70541416af4fee243f946f4c0e4e5193df7d2`. The integrated [capture/repair metrics](round5-observability-evidence/integrated-workers.json) and [default remote-retention](round5-observability-evidence/integrated-default-retention.json) suites also passed. Native FUSE capture runs only the server in an owned private user/mount namespace and fails on cleanup errors.

The [gate record](round5-observability-evidence/checks.json) distinguishes the 210-test full library run from the four typed-error tests repeated after the extraction. The first hardened streaming-test invocation used the wrong proxy event field and failed; it was corrected to `kind` and rerun. Initial worker-harness failures (wrong volume path, missing FUSE privilege context, disconnected mounts at cleanup) were retained locally; the published reports are the corrected passing invocations.

This advances #80 and preserves the #77 default-retention work in its parent PR. Detached background errors still lack a durable worker/operation correlation scheme, and exhaustive per-worker fault coverage remains unfinished. No production throughput SLA, physical multi-host/power-loss qualification, independent FUSE helper, public scoped-token issuer, or completion of all issues is claimed.
