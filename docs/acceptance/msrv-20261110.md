# Rust floor (MSRV) qualification on main `8b5a5e3` (2026-11-10)

Scope: issue #75, minimum Rust floor only. This record qualifies the declared
floor with a real, executed compiler run against an unmodified checkout. It
changes no dependency, manifest, lockfile or floor, and it closes nothing.

**Verdict:** the declared floor **PASSES** on the audited source. On Linux with
rustc/cargo 1.88.0, `cargo check --locked --lib` (default features) exits 0
with no diagnostics. The exact-commit CI gate is recorded separately below and
is **not** part of this MSRV qualification.

- HEAD: `8b5a5e36fe6824e7921cf2126c3b86ec47725254` (branch
  `codex/msrv-floor-75`), working tree clean (`git status --porcelain` empty)

- Declared floor: `rust-version = "1.88"` in `Cargo.toml`.
- Gate toolchain: `channel = "1.99.1"` in `rust-toolchain.toml`; this is not
  the floor and is not exercised by this record.

## Environment

- Image: `rust:1.88.0-bookworm` (Debian 12.11), pulled for this run. Linux
  kernel 7.2.12 (orbstack), host architecture `aarch64-unknown-linux-gnu`.
- `RUSTUP_TOOLCHAIN=1.88.0` was set explicitly, so the checkout's
  `rust-toolchain.toml` override (`1.99.1`) did not apply. `rustup show
  active-toolchain` reported `1.88.0-… (overridden by environment variable
  RUSTUP_TOOLCHAIN)` both inside and outside the checkout.
- Compiler evidence taken before the check:
  `rustc 1.88.0 (6b00bc388 2025-06-23)`, `cargo 1.88.0 (873a06493 2025-05-10)`,
  host LLVM 20.1.5. System compiler `cc` 12.2.0 and OpenSSL 3.0.16 headers
  were present, so `rdkafka-sys` (enabled by default feature `kafka-wake`) built
  its bundled librdkafka.
- Isolation: the checkout was mounted read-only and the run used a dedicated
  target volume and a dedicated cargo cache, not the shared 1.99.1 caches;
  `CARGO_BUILD_JOBS=2`, `CARGO_INCREMENTAL=0`, dev/test debug info disabled.
- The checkout's Git common directory (`.git` of the main checkout) was mounted
  read-only only so HEAD/dirty state could be verified. The source itself was
  read-only for the whole run.

## Limitations

- Only `cargo check --locked --lib` with default features was run. Binaries,
  integration tests, `--all-targets`, `--features pando-lab`, and the
  `--no-default-features` Blob profile were not exercised with 1.88.0, and
  `--locked` means only the committed resolution was tested.
- Only the `aarch64-unknown-linux-gnu` target was run. The CI runners
  (`ubuntu-22.04`) are x86-64 with a newer glibc, so this is not a statement
  about every host target.
- No automated MSRV gate exists in CI. Adding one (for example installing
  1.88.0 alongside the 1.99.1 gate tools and running the check above) is a
  separate follow-up task and is deliberately not implemented here.
