# Blob Compaction & Default-Off Safe Destructive GC (`Refs #122`)

This module ([`safe_gc.rs`](../src/storage_lifecycle/safe_gc.rs)) delivers safe physical deletion fencing, unified retention-root reconciliation, `#184` pack-cover `GcEligible` gating, live reader quiescence, monotonic anti-ABA physical key management, and two-phase read-back Blob compaction wired into Rootyard's real storage maintenance scheduler/worker for Issue `#122`.

## Invariants & Safety Model

1. **Default-Off Destructive GC (`SAFE_GC_DESTRUCTIVE_ENABLED_BY_DEFAULT = false`)**:
   - [`GcMode::DisabledByDefault`](../src/storage_lifecycle/safe_gc/model.rs) and `ROOTYARD_BLOB_SAFE_GC_DESTRUCTIVE=false` reject physical deletion by default, while [`BlobStore::delete`](../src/blob_store/readback.rs) stays `DeleteDisabled`.
   - Arming requires a sealed [`SafeGcArmReceipt`](../src/storage_lifecycle/safe_gc/model.rs) with an Ed25519 signature bound to the repository trust bundle, `operator_opt_in = true`, non-TTL/non-cache origin, matching live `incarnation_id`/`incarnation_epoch`, and explicit lane prerequisites:
     - `AuthorityLane::SingleNodePg`: live PostgreSQL tx sequence, `repositories.gc_epoch` fence, and exclusive reader barrier epoch.
     - `AuthorityLane::DistributedRefCas`: Ed25519-signed quorum commit evidence, `#151` hold-bridge evidence over the complete live hold set, and `#153` backup-root evidence, each pinned by [`SafeGcRepoTrustConfig`](../src/storage_lifecycle/safe_gc/dist_auth.rs) and authenticated through the `#151` `GroupConsensusVerifier` keyring (never async PG projection alone).
2. **Authoritative `DeletionProof`, `#184` `GcEligible` Bridge & Live Reader Quiescence**:
   - [`build_and_verify_deletion_proof`](../src/storage_lifecycle/safe_gc/proof.rs) and [`store_verify.rs`](../src/storage_lifecycle/safe_gc/store_verify.rs) bind `incarnation`, exact `membership_generation` + `membership_digest`, live Git refs, all 6 retention producers (`pull_request`, `ci_pin`, `workspace`, `namespace`, `lfs`, `backup`), global holds, in-flight decisions, paired PG/Ref-CAS cursors, verified [`GroupClosureReceipt`](../src/storage_lifecycle/safe_gc/model.rs) chains, and both `.pack`/`.idx` candidate keys.
   - [`retention_bridge.rs`](../src/storage_lifecycle/safe_gc/retention_bridge.rs) evaluates `#184` [`RetentionClassificationIndex`](../src/ref_store/core/ref_version/pack_cover/retention_class.rs) requiring `PackRetentionState::GcEligible` while ignoring TTL/cache/projection hints; [`quiescence.rs`](../src/storage_lifecycle/safe_gc/quiescence.rs) and `ref_store_core_serving_reads` enforce live reader drain watermarks without constant flags.
3. **Two-Phase Read-Back Compaction & Remote Staging Cleanup**:
   - [`execute_two_phase_compaction`](../src/storage_lifecycle/safe_gc/compaction.rs) keeps `Arc<TempViewLease>` alive across `BlobStore::get_to_file_with_owner`, excludes pack-pinned active packs, verifies self-contained `git verify-pack -v` + repository-wide `git fsck --full --strict` (`SHA-1` & `SHA-256`) before CAS publish, and cleans abandoned staging uploads via [`reclaim_abandoned_compaction_staging`](../src/storage_lifecycle/safe_gc/executor.rs).
4. **Continuous Provider Fence, Terminal Outcomes & Production Maintenance Entry**:
   - [`OpenDalS3GcProvider`](../src/storage_lifecycle/safe_gc/provider_delete.rs) executes real OpenDAL S3 wire `PUT`/`HEAD`/`DELETE` under [`ActiveDeleteFence`](../src/storage_lifecycle/safe_gc/domain.rs), distinguishing `ConfirmedDeleted`, `AlreadyAbsent`, and `OutcomeUnknown`, and [`pg_maintenance.rs`](../src/storage_lifecycle/safe_gc/pg_maintenance.rs) integrates with [`scheduler.rs`](../src/storage_lifecycle/scheduler.rs), [`worker.rs`](../src/storage_lifecycle/worker.rs), and [`fence.rs`](../src/storage_lifecycle/fence.rs).
5. **Production Ref-CAS Commit Cutpoint Publication**:
   - [`RefCasCommitCutpointPublisher`](../src/storage_lifecycle/safe_gc/refcas_publisher.rs) atomically seals `<storage_root>/safe-gc/refcas/<repo_id>.json`, including the `#151` quorum attestation, after each production Ref-CAS apply (including the install-before-commit window); `InProcessRefCasBackend::{set_abort_after_install_once,register_safe_gc_repo,publish_cutpoint}` in [`coordinator.rs`](../src/pulls/remote_merge_finalizer/coordinator.rs) wire publication and the live authority registry into the real `PullRemoteMergeProducer::execute_merge` path. Destructive `DistributedRefCas` sweeps resolve [`ProductionRefCasAuthoritySource`](../src/storage_lifecycle/safe_gc/pg_maintenance_dist.rs) (live registered state machine first, sealed attestation second), re-verify it with `GroupConsensusVerifier`, re-seal the arm against the pass's PG fence, and still require an exact PG `ref_cas_projection_cursors`/unprojected-job match, so a PostgreSQL ref sequence alone can never unlock deletion.
6. **Distributed `pending_delete` Restart Fence**:
   - A cold worker reopen clears the un-held in-memory `pg_exclusive_barrier_epoch`, so an interrupted `pending_delete` batch refuses `reconcile_pending_delete_after_restart_fenced` with `StaleDeleterFenced` until the live PostgreSQL `gc_epoch` is re-acquired and `rebind_pending_delete_live_pg_fence` updates the persisted proof. The resumed pass audits `rebind_pending_delete_pg_fence`, deletes only the remaining keys, and leaves the replacement pack `git fsck --full --strict` clean.
   - [`pg_child_worker.rs`](../tests/storage_safe_gc_support/pg_child_worker.rs) runs the scheduled worker in a genuinely separate OS process, proving the production cutpoint source, trust bundle and PG fence survive a worker restart without relying on the parent's in-memory authority handle.
7. **Unbounded Install-to-Commit In-Flight Decisions**:
   - A Ref-CAS decision that is installed but not yet committed is persisted as a `Pending` in-flight record with unknown protection. [`proof.rs`](../src/storage_lifecycle/safe_gc/proof.rs), [`store_verify.rs`](../src/storage_lifecycle/safe_gc/store_verify.rs), [`store.rs`](../src/storage_lifecycle/safe_gc/store.rs) and [`retention_bridge.rs`](../src/storage_lifecycle/safe_gc/retention_bridge.rs) refuse deletion for that unbounded window (pinning all active/retired packs) and lift the block only after the commit or cancel is durably observed.
