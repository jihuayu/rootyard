# Coordinated PG Cutpoint + Raft Index + Blob Closure Paired Backup & New-Incarnation Restore (`#153`)

This document specifies the paired backup and clean-room new-incarnation restore engine implemented under [`src/maintenance/paired_raft_backup.rs`](../src/maintenance/paired_raft_backup.rs) for Blob-only Pando (`PostgreSQL 17 schema 152 / format 32 + live 3-voter mTLS raft-node + OpenDAL BlobStore + stock Git`).

Classification tags used below:
- **CurrentCodeFact**: schema-152 / format-32 backup and catalog contracts, triggers, and Raft runtime ([`src/backup/catalog.rs`](../src/backup/catalog.rs), [`migrations/144_ref_store_core_roots_decisions.sql`](../migrations/144_ref_store_core_roots_decisions.sql), [`migrations/145_ref_store_serving.sql`](../migrations/145_ref_store_serving.sql), [`migrations/149_ref_cas_event_projection.sql`](../migrations/149_ref_cas_event_projection.sql), [`migrations/151_repository_lifecycle.sql`](../migrations/151_repository_lifecycle.sql), [`crates/refcas-log/src/bin/raft-node.rs`](../crates/refcas-log/src/bin/raft-node.rs)).
- **EnforcedRestoreProtocol**: live 3-voter mTLS Raft quorum + `EnsureReadIndex` backend ([`mtls_raft.rs`](../src/maintenance/paired_raft_backup/mtls_raft.rs), [`mtls_wire.rs`](../src/maintenance/paired_raft_backup/mtls_wire.rs)), durable PostgreSQL + Raft `freeze`/`thaw` fence covering `repo_access`, holds, Ref-CAS writes, and deleters ([`durable_freeze_gate.rs`](../src/maintenance/paired_raft_backup/durable_freeze_gate.rs), [`durable_guarded_ops.rs`](../src/maintenance/paired_raft_backup/durable_guarded_ops.rs)), standard `schema 152` / `format 32` (`pg_dump`/`pg_restore`) paired backup & clean-room new-incarnation installation + boot ([`format30_paired.rs`](../src/maintenance/paired_raft_backup/format30_paired.rs), [`format30_boot.rs`](../src/maintenance/paired_raft_backup/format30_boot.rs)), and separated quorum vs local WAL proofs ([`quorum_wal.rs`](../src/maintenance/paired_raft_backup/quorum_wal.rs), [`raft_barrier.rs`](../src/maintenance/paired_raft_backup/raft_barrier.rs), [`peer_groups.rs`](../src/maintenance/paired_raft_backup/peer_groups.rs)), server-side per-peer Ed25519 durable attestations ([`peer_attestation.rs`](../src/maintenance/paired_raft_backup/peer_attestation.rs), [`peer_attestation_rpc.rs`](../src/maintenance/paired_raft_backup/peer_attestation_rpc.rs), [`wal_voters.rs`](../src/maintenance/paired_raft_backup/wal_voters.rs)), and the production freeze/incarnation/deleter guard wiring ([`production_runtime.rs`](../src/maintenance/paired_raft_backup/production_runtime.rs), [`src/maintenance.rs`](../src/maintenance.rs)).
- **MeasuredEvalBaseline**: reproducible SHA-1 & SHA-256 stock-Git archive/restore/tamper timings and closure byte counts from [`scripts/eval_paired_raft_backup.py`](../scripts/eval_paired_raft_backup.py).

## 1. Production 3-Voter mTLS Quorum, Durable `repo_access` Freeze/Thaw & Paired Archive Cutpoint (`EnforcedRestoreProtocol`)

1. **Authenticated Live 3-Voter mTLS Raft Quorum (`MtlsLiveRaftBackend`)**:
   - [`MtlsLiveRaftBackend`](../src/maintenance/paired_raft_backup/mtls_raft.rs) connects over TLS 1.3 mutual-TLS (`rustls::ClientConnection`, verifying CA + `raft-node-{id}.refcas.internal` SANs and binding each voter's X.509 leaf SHA-256 into `group_membership_digest` and [`VoterWalAck`](../src/maintenance/paired_raft_backup/raft_barrier.rs)).
   - Commits execute real `openraft` majority `ClientWrite` + `EnsureReadIndex` + `TriggerSnapshot`, minting [`QuorumCommitReceipt`](../src/maintenance/paired_raft_backup/raft_barrier.rs) across `> N/2` authenticated live voters while independently verifying `local_node_id` replica catch-up ([`LocalWalApplyReceipt`](../src/maintenance/paired_raft_backup/raft_barrier.rs)).
2. **Durable PostgreSQL + Raft `freeze`/`thaw` Covering `repo_access`, Holds, Ref-CAS Writes & Deleters**:
   - [`enter_durable_pg_raft_freeze`](../src/maintenance/paired_raft_backup/durable_freeze_gate.rs) persists `ALTER DATABASE ... SET rootyard.paired_backup_freeze`, `pando_storage_authorities.remote_delete_fenced = true`, bumped `ref_store_decision_scopes` versions across `repo_access`, `repo_lifecycle`, and `authority`, and `DurableRaftFreezeRecord::Frozen` across active + peer 3-voter mTLS Raft clusters (surviving connection drops and `raft-node` restarts).
   - Guarded mutators ([`upsert_repo_access_collaborator_guarded`](../src/maintenance/paired_raft_backup/durable_guarded_ops.rs), [`propose_raft_hold_guarded`](../src/maintenance/paired_raft_backup/durable_guarded_ops.rs), [`propose_raft_ref_write_guarded`](../src/maintenance/paired_raft_backup/durable_guarded_ops.rs), [`execute_deleter_guarded`](../src/maintenance/paired_raft_backup/durable_guarded_ops.rs)) deterministically reject concurrent writes while frozen and resume only after [`thaw_durable_pg_raft_freeze`](../src/maintenance/paired_raft_backup/durable_freeze_gate.rs) verifies [`SealedArchiveReceipt`](../src/maintenance/paired_raft_backup/raft_barrier.rs) and the paired archive.
   - Kernel enforcement: [`pg_write_fence.rs`](../src/maintenance/paired_raft_backup/pg_write_fence.rs) opens a dedicated `REPEATABLE READ` backend that holds `LOCK TABLE public.<every base table> IN SHARE MODE` for the whole frozen window. PostgreSQL itself rejects any concurrent `INSERT`/`UPDATE`/`DELETE`/DDL (including a superuser session that overrides the session read-only GUC) with `lock_timeout`, and thaw releases the fence only after the archive/quorum seals verify.
3. **Full PG + Blob + Multi-Group Raft Archive**:
   - [`create_format30_paired_raft_backup`](../src/maintenance/paired_raft_backup/format30_paired.rs) delegates the PostgreSQL (`pg_dump --format=custom --schema=public --snapshot`) and OpenDAL Blob closure archive to [`crate::backup::create`](../src/backup/snapshot.rs) using format 32 and the exact schema-152 migration list, binding `metadata.dump`, `blob/...`, `PgCutpointProof`, and active + peer [`PeerRaftCutpointProof`](../src/maintenance/paired_raft_backup/peer_groups.rs)s into [`Format30PairedManifest`](../src/maintenance/paired_raft_backup/format30_paired.rs).

## 2. Clean-Room Paired Restore & New-Incarnation Installation + Boot (`EnforcedRestoreProtocol`)

1. **Full PostgreSQL and Blob restore** delegates to [`restore_and_boot_format30_new_incarnation`](../src/maintenance/paired_raft_backup/format30_boot.rs). [`verify_format30_paired_archive`](../src/maintenance/paired_raft_backup/format30_paired.rs) verifies both `COMPLETE` seals and binds the outer manifest and PostgreSQL cutpoint to the inner archive's actual format, schema and identity. The existing v1 envelope still uses the `format30/` path and `format30_pg` field. It verifies historical format 30 with schema 151 and current format 32 with schema 152. The directory name remains part of the envelope layout. The sealed numeric pair and frozen catalog determine the schema. [`crate::backup::restore`](../src/backup/restore.rs) requires the exact producing binary and a fresh target. It checks the restored PostgreSQL catalog for the archive's declared schema and rebuilds the Blob closure under `OfflineRestorePermit`. Use the original trusted producer to restore a format-30 archive, then upgrade separately.
2. **Actual Installation & Boot of the New Incarnation**:
   - Rotates `cluster_authority.incarnation` (`new_cluster_incarnation`) and `pando_storage_authorities` (`new_storage_authority_id`, bumped `generation`, `restore_generation >= new_deleter_epoch`, bumped `authority_epoch`), revokes all pre-restore `public.tokens`, cancels `OPEN` `ref_store_publication_decisions`, and advances `ref_store_decision_scopes` (`repo_access`, `repo_lifecycle`, `authority`) to `new_authz_floor`.
   - Boots fresh 3-voter mTLS `raft-node` clusters (active + peer groups) with the restored gates/refs/holds, `NewIncarnationAuthority`, and `new_authz_floor`, aligning `public.ref_cas_projection_cursors` (`verify_pg_restored_cursors`) and enforcing post-restore `repo_access`, Smart-HTTP Blob reads/pushes, and Ref-CAS quorum writes.

## 3. Freeze/Attestation/Incarnation Hardening (`EnforcedRestoreProtocol`)

1. **PG pooled-session `READ ONLY` reset & verified write-session exit**:
   - [`enter_durable_pg_raft_freeze`](../src/maintenance/paired_raft_backup/durable_freeze_gate.rs) now unconditionally re-issues `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY` on **both** the `Ok` and `Err` paths, so a pooled connection never leaks a read-write session back to the pool.
   - The former fire-and-forget `pg_terminate_backend` is replaced by [`terminate_and_await_other_pg_sessions`](../src/maintenance/paired_raft_backup/pg_freeze_settings.rs): every `pg_terminate_backend(pid)` boolean is inspected (fail-closed on `false`/`NULL`), then `pg_stat_activity` is polled until no other client backend of `current_database()` survives, bounded by a 5 s deadline.
   - [`verify_no_active_pg_writers`](../src/maintenance/paired_raft_backup/pg_freeze_settings.rs) runs immediately before the `RepeatableRead` cutpoint transaction, refusing capture while any other backend still holds a transaction/xid. [`verify_no_active_pg_writers_except_fence`](../src/maintenance/paired_raft_backup/pg_freeze_settings.rs) applies the same rule while excluding only the SHARE-mode fence backend (identified by `pg_backend_pid()` and `backend_xid IS NULL`).
2. **Server-side Ed25519 per-peer durable attestations**:
   - [`peer_attestation.rs`](../src/maintenance/paired_raft_backup/peer_attestation.rs) defines `PeerDurableAttestationClaims`/`PeerDurableAttestation`, canonical `rootyard-peer-durable-attestation-v1` signing, `derive_voter_uuid_bound` (`rootyard-mtls-voter-uuid-v2`, binding the X.509 leaf SHA-256 **and** the Ed25519 public key), and the per-voter mTLS `PeerAttestationDaemon`.
   - [`peer_attestation_rpc.rs`](../src/maintenance/paired_raft_backup/peer_attestation_rpc.rs) verifies the voter's own `raft-node` replica (`Metrics`, `InspectReplicaKv`, replayed `state_digest`/`snapshot.checksum`, fsynced `sm.sqlite3`/`log.sqlite3`) before signing `"commit"`/`"cutpoint"` claims.
   - `PeerAttestorState::verify_local_group_epoch` cross-checks the requested `group_epoch` against **three** durable local-replica sources (`refcas/cluster_incarnation`, `refcas/group_epoch`, and the replayed `refcas/cmd/00000001` `InitializeGate`), requiring agreement and equality before any signature; stale requests return `StaleIncarnation { field: "group_epoch" }`, divergent sources return `CutpointSkew`, and cutpoint replay additionally requires every replayed gate epoch to equal the signed value.
   - Every [`VoterWalAck`](../src/maintenance/paired_raft_backup/raft_barrier.rs) must now carry a verified `"commit"` attestation bound to `(group_id, group_epoch, log_id, command_sha256, wal_record_digest)`, and every `RaftCutpointProof`/`PeerRaftCutpointProof` must carry `> N/2` distinct `"cutpoint"` attestations bound to the archived voter set and cutpoint digests (`verify_cutpoint_attestations`).
   - `WalSyncedRaftBackend` persists per-voter `0o600` `.voter{slot}.pk8` Ed25519 keys and `.voters` bindings ([`wal_voters.rs`](../src/maintenance/paired_raft_backup/wal_voters.rs)) and signs each local `VoterWalAck` itself.
3. **Pristine target Raft incarnation check on restore**:
   - [`verify_pristine_new_incarnation_target`](../src/maintenance/paired_raft_backup/mtls_raft.rs) probes **100%** of the configured target voters: a target `group_membership_digest` must differ from the source, `sm_summary.kv_count == 0` with no active snapshot, and `refcas/head_seq`, `refcas/cluster_incarnation`, `refcas/group_epoch`, and `refcas/paired_freeze` must be absent.
   - [`restore_and_boot_format30_new_incarnation`](../src/maintenance/paired_raft_backup/format30_boot.rs) runs it for the active and every peer target Raft cluster **before** `crate::backup::restore`, with `forbidden_incarnations = {source_cluster_incarnation, source_storage_authority_id}`.
4. **Freeze / restored-incarnation / deleter-epoch guards wired into production paths**:
   - [`enforce_maintenance_pg_write_guard`](../src/maintenance/paired_raft_backup/pg_freeze_settings.rs) is enforced in [`src/maintenance.rs`](../src/maintenance.rs) `resolve`, `retire_resolved_journals`, and `retire_if_resolved` so audit-gap resolution and journal retirement fail closed during a freeze, database-wide read-only fence, or `remote_delete_fenced`.
   - [`production_runtime.rs`](../src/maintenance/paired_raft_backup/production_runtime.rs) adds `PairedProductionRuntimeGuard::{commit_ref_write, run_projection_worker_step, execute_fenced_pack_delete}` and `WorkerProjectionTicket`, re-exported through [`src/maintenance.rs`](../src/maintenance.rs), so ref writes, projection-worker steps, and pack deletes all re-check the restored `cluster_incarnation`/`history_incarnation`, bumped `group_epoch`/`authz_floor`, the durable deleter epoch, and the active freeze.
   - [`admission_guard.rs`](../src/maintenance/paired_raft_backup/admission_guard.rs) exposes `admit_writer_grant`/`admit_decision_execution`/`admit_deleter_lease` aliases of the same fail-closed admission checks.

## 4. Four Production Guarantees (`EnforcedRestoreProtocol`)

1. **Durable WAL/SM bytes bound to Raft commits**: [`wal_file_digest.rs`](../src/maintenance/paired_raft_backup/wal_file_digest.rs) fsyncs and hashes each voter's `log.sqlite3`/`sm.sqlite3`, rejects missing or empty files, and binds the committed `last_applied.index` into the `rootyard-mtls-peer-wal-v3` signature.
2. **Freeze/writer serialization**: `PAIRED_FREEZE_JOURNAL_LOCK_KEY` ([`pg_freeze_settings.rs`](../src/maintenance/paired_raft_backup/pg_freeze_settings.rs)) is exclusive for freeze entry and shared by [`journal::retire`](../src/maintenance.rs), while cross-connection thaw terminates stale sessions and restores `READ WRITE` on the original pool.
3. **Production startup wiring**: [`src/standalone.rs`](../src/standalone.rs) calls `install_production_serving_guard` and `ensure_serving_database_unfrozen` ([`startup_wiring.rs`](../src/maintenance/paired_raft_backup/startup_wiring.rs)), so serving refuses startup or drains when a freeze is latched. The same wiring optionally spawns the voter's co-located mTLS Ed25519 attestor from `ROOTYARD_PAIRED_RAFT_ATTESTOR_JSON` before connecting the live Raft backend, and `src/bin/rootyard-peer-attestor.rs` provides the identical standalone sidecar process used by the multi-process tests.
4. **Frozen-until-ready multi-peer restore**: [`format30_boot.rs`](../src/maintenance/paired_raft_backup/format30_boot.rs) rejects an incomplete peer set up front, rotates `history_incarnation`/`authority_epoch`/`group_epoch` across PG and every restored Raft group, and unfreezes only after PG cursors and 100% of active + peer cutpoint attestations verify.

## 5. Fence-Hold Continuity, X.509 Caller Authorization & Restored Realm Re-Homing (`EnforcedRestoreProtocol`)

1. **Fence held through archive *and* receipt publication**:
   - [`pg_write_fence.rs`](../src/maintenance/paired_raft_backup/pg_write_fence.rs) `verify_held` is one round-trip probe that requires the same `pg_backend_pid()`, one granted `SHARE` lock per `public` base table, an unchanged public base-table count, and `backend_xid IS NULL`; any drift is `FreezeNotHeld`.
   - [`durable_guarded_ops.rs`](../src/maintenance/paired_raft_backup/durable_guarded_ops.rs) adds `verify_fence_intact_for_publication`, which re-proves the SHARE fence, zero concurrent PG writers except the fence backend, `pando_storage_authorities.remote_delete_fenced`, `verify_still_frozen_on`, every peer `committed_quorum_index >= barrier_log_id.index`, and `verify_freeze_barrier_active` before any archive or receipt is published.
   - [`format30_paired.rs`](../src/maintenance/paired_raft_backup/format30_paired.rs) re-runs that proof at four boundaries (before the PG cutpoint, after `crate::backup::create`, before `COMPLETE`+rename, and after archive verification before `SealedArchiveReceipt::mint`); a failed proof removes the partial/published directory and returns `FreezeNotHeld`.
   - `DurableFreezeHandle` exposes the `#[doc(hidden)]` `fault_drop_fence_stage` injection seam used only by the ignored gate-7 test.
2. **Durable WAL digest and quorum-reached cutpoint bound into attestations**:
   - `PeerDurableAttestationClaims` now carries `durable_sqlite_sha256`; [`peer_attestation.rs`](../src/maintenance/paired_raft_backup/peer_attestation.rs) rejects a missing/short/all-zero digest, and [`wal_voters.rs`](../src/maintenance/paired_raft_backup/wal_voters.rs) fills it with the real SHA-256 of each voter slot's fsynced WAL (or a tagged empty-slot digest).
   - `AttestCutpointRequest` gains `min_committed_index`; the voter refuses (`FreezeNotHeld`) unless `expected_seq > 0`, `min_committed_index >= expected_seq`, `committed_applied_index >= expected_seq`, `committed_applied_index >= min_committed_index`, and `last_log_index >= committed_applied_index`.
   - [`raft_barrier.rs`](../src/maintenance/paired_raft_backup/raft_barrier.rs) `verify_cutpoint_attestations` repeats the committed-index reach, the hex/all-zero `durable_sqlite_sha256` check, and every quorum attestation must come from a distinct archived voter.
3. **Peer attestor callers authorized by X.509 identity**: [`peer_caller_auth.rs`](../src/maintenance/paired_raft_backup/peer_caller_auth.rs) extracts the leaf `subjectAltName` DNS entries, requires the pinned `raft-client.refcas.internal` identity, and intersects the presented chain with either the explicit `--allow-caller-sha256` allowlist or the configured `raft-client` leaf digest before any request is dispatched; refusals return a framed `{"Error": ...}` response. The allowlist is threaded through `ROOTYARD_PAIRED_RAFT_ATTESTOR_JSON` and [`src/bin/rootyard-peer-attestor.rs`](../src/bin/rootyard-peer-attestor.rs).
4. **Restored A3/A4 realm re-homing**: [`format30_realm_rehome.rs`](../src/maintenance/paired_raft_backup/format30_realm_rehome.rs) leaves every historical A3/A4 ledger row byte-for-byte immutable under the source realm: it rotates only the live gate/protocol/serving pointers and derived usage counters (`history_incarnation`, `authority_epoch`, `group_epoch`, `pack_mode`, `decision_required`, pack usage) and re-runs the canonical A3 acquire -> [`ProtectedUploader`](../src/blob_store/protected.rs) -> A4 register/verify/commit pipeline in the new realm for every restored pack pair, replaying further ref chunks through [`format30_rebind_plans.rs`](../src/maintenance/paired_raft_backup/format30_rebind_plans.rs). [`format30_boot.rs`](../src/maintenance/paired_raft_backup/format30_boot.rs) calls it inside the `session_replication_role = replica` transaction.
5. **Publish-last volume commit, multi-plan rebind and the normal paired write path**:
   - [`format30_boot.rs`](../src/maintenance/paired_raft_backup/format30_boot.rs) commits the Raft `boot_thaw` inside the fallible block: a pre-commit quorum loss returns `BootThawRefused`, while a post-commit leader-snapshot failure stays `StateMachine` and is never reclassified as a thaw refusal. All four PostgreSQL fences (`remote_delete_fenced`, `default_transaction_read_only`, `paired_backup_freeze`, `restore_in_progress`) stay continuously armed across `publish_staged_dir_noreplace` (`RENAME_NOREPLACE`) + `sync_parent_dir`; PostgreSQL is cleared only after publication and the `.rootyard-restoring` admission guard is removed last. `restore_and_boot_format30_with_pre_thaw_hook` injects a `before_thaw` action after all verification and before the thaw so the ignored gate-10 test can kill a quorum mid-window.
   - **64 MiB A4 Verifier Closure Contract** (`CurrentCodeFact` + `EnforcedRestoreProtocol`): [`PackVerifier::verify`](../src/ref_store/core/pack_commit/verifier/mod.rs) validates each plan against the active membership carried in `old_memberships`, and [`verifier/validate.rs`](../src/ref_store/core/pack_commit/verifier/validate.rs) sums every `old_packs + new_packs` artifact and refuses a closure above `VERIFIER_MAX_TOTAL_BYTES` (`64 MiB`); [`verifier/download.rs`](../src/ref_store/core/pack_commit/verifier/download.rs) additionally enforces `VERIFIER_MAX_OBJECTS` (`16,384`). Because old packs stay in every later plan, archive admission must reject an oversized closure before any rebind starts. Multi-pack archives are consolidated by a streaming `64 KiB` `git pack-objects`, and any repository whose archived or consolidated artifact closure exceeds the bound fails closed with `PairedBackupError::RepositoryClosureExceedsVerifierBudget`, leaving the target volume unpublished and PostgreSQL fenced. Delta 15 enforces the same bound *before publication*: [`format30_paired.rs`](../src/maintenance/paired_raft_backup/format30_paired.rs) (and the standalone [`backup.rs`](../src/maintenance/paired_raft_backup/backup.rs) exporter) recomputes the per-repository artifact bytes from the produced closure entries and refuses above `VERIFIER_MAX_TOTAL_BYTES` before sealing/writing `manifest.json`, before writing `COMPLETE`, and before the destination `fs::rename`, while the `PartialDirGuard` removes the `.partial` work directory, so a refused backup never creates a destination and leaves no staging debris. [`freeze_drain.rs`](../src/maintenance/paired_raft_backup/freeze_drain.rs) commits each A3 `AcquireHoldBatch` in `MAX_BATCH_ARTIFACTS` (`16` artifact slots = 8 pack/idx pairs) chunks, so a repository above eight pairs registers its complete hold set across several bounded Raft commands.
   - [`format30_pack_consolidate.rs`](../src/maintenance/paired_raft_backup/format30_pack_consolidate.rs) bounds one rebind plan by both `MAX_PLAN_REFS` and a per-ref ACK budget (`chunk_refs_for_plans` / `MAX_REBIND_REF_ACK_BYTES`), and [`format30_realm_rehome.rs`](../src/maintenance/paired_raft_backup/format30_realm_rehome.rs) replays every further chunk through [`format30_rebind_plans.rs`](../src/maintenance/paired_raft_backup/format30_rebind_plans.rs) `commit_followup_ref_plan`, ref-only plans that re-capture the baseline (which already carries the memberships the first plan committed) so an archive holding more than 128 refs still rebinds through canonical A4 plans; `select_packs_for_rebind_with_limit` fails closed with `RepositoryClosureExceedsVerifierBudget` (attributed to the repository) whenever the consolidated `.pack + .idx` pair cannot fit the verifier total-byte bound.
   - [`format30_boot_raft.rs`](../src/maintenance/paired_raft_backup/format30_boot.rs), [`peer_groups.rs`](../src/maintenance/paired_raft_backup/peer_groups.rs) and [`restore.rs`](../src/maintenance/paired_raft_backup/restore.rs) replay `CommitRefsRequest` in `MAX_PLAN_REFS` chunks that each advance the freshly initialized gate revision by exactly one.
   - [`startup_wiring.rs`](../src/maintenance/paired_raft_backup/startup_wiring.rs) serializes each database's PostgreSQL snapshot read + `spawn_blocking` Raft CAS-delta apply under one per-database `Arc<tokio::sync::Mutex<()>>` whose **owned** `lock_owned()` guard is moved into the blocking closure, so a caller cancelled at an await point still holds the lock until the blocking Raft apply finishes, then resolves the binding without holding a pooled connection while waiting, and enforces `TerminalKind::Committed` (`ensure_raft_commit_refs_committed`); [`startup_wiring_tests.rs`](../src/maintenance/paired_raft_backup/startup_wiring_tests.rs) covers both the read-before-apply ordering and that cancelled-caller lock retention. It binds one `PairedWriteBinding` per *database name* (`install_paired_write_raft_binding`/`PairedWriteRaftScopeGuard`), and [`receive.rs`](../src/blob_git_gateway/receive.rs) refuses a normal push while PostgreSQL or the bound Raft cluster is frozen, then after the durable terminal mirrors the exact PostgreSQL -> Raft CAS delta ([`format30_pg_raft_sync.rs`](../src/maintenance/paired_raft_backup/format30_pg_raft_sync.rs): `Absent -> Oid`, `Present(old) -> Oid`, `Present(old) -> Delete`, chunked at `MAX_PLAN_REFS`). `MtlsLiveRaftBackend::sync_cached_state_machine` refreshes a handle that may not have observed the gateway's own commits before `enter_durable_pg_raft_freeze` registers the closure holds, so the freeze record always covers the full log.
